# Аудит проекта Apple Garden

Дата: 2 октября 2026. Состояние на коммит `e511f1e`.

Проект — одностраничный сайт семейного ресторана Apple Garden (Салар, Ташкентская область). Это концепт для портфолио, ресторан его не заказывал. Три файла: `index.html`, `style.css`, `script.js`, без сборки, зависимостей и тестов.

Скриншоты до изменений сняты на ширине 360, 820 и 1440 px (Chromium, Playwright).

---

## Что уже хорошо

- **Простая основа.** Статический HTML без фреймворков. Грузится быстро, ломаться почти нечему.
- **Семантика на базовом уровне.** Есть `lang="ru"`, `header`, `nav`, `section`, `footer`, один `h1`, у iframe карты есть `title`.
- **Реальные данные.** Телефон, plus code адреса, часы, рейтинг и отзывы взяты из открытой карточки ресторана, а не придуманы.
- **Правильные мелочи.** Телефон кликабельный (`tel:`), у внешних ссылок стоит `rel="noopener"`, карта грузится лениво (`loading="lazy"`).
- **Цвета в переменных.** Палитра частично вынесена в CSS-переменные (`:root`), тему легко менять.
- **Есть адаптив.** Две контрольные точки (900 и 760 px), на 360 px нет горизонтальной прокрутки.
- **В репозитории нет секретов.**

## Дизайн: признаки «сгенерированного» сайта

- **Шаблонная структура.** Центрированный hero, полоса из четырёх иконок, «о нас» с блоком цифр, сетка карточек с эмодзи, отзывы карточками, контакты. Такой порядок встречается в тысячах шаблонов.
- **Фальшивые фотографии.** Блок «О ресторане» и вся «Галерея» состоят из градиентных прямоугольников на месте фото (`style.css:177–186`, `204–209`). Раздел «Галерея» без единого снимка выглядит как недоделка.
- **Эмодзи вместо графики.** 🍏 в логотипе и эмодзи в полосе преимуществ, карточках меню и контактах. На разных системах они выглядят по-разному, скринридер зачитывает их вслух («красное яблоко»).
- **Шрифты по умолчанию.** Playfair Display + Inter — самая частая пара в сгенерированных макетах. К тому же грузятся 8 начертаний с Google Fonts.
- **Всё одинаковое.** Скругление 18 px и одна и та же тень у всех блоков, отступ 96 px у всех секций, все заголовки по центру. Иерархии и ритма нет.
- **Glassmorphism в шапке.** `backdrop-filter: blur(8px)` при прокрутке.
- **Лишняя анимация.** Подпрыгивающая стрелка «вниз» крутится бесконечно, `prefers-reduced-motion` не учитывается.
- **Палитра без системы.** Три зелёных, два кремовых и золотой. Акцентный золотой на светлом фоне нечитаем, контраст 2,1–2,4:1.

## Тексты

- **Клише:** «блюда, которые готовят с душой», «вкус, проверенный временем», «уделяет внимание каждой детали», «чтобы каждый визит запоминался», «идеальное завершение трапезы», «будем рады видеть вас».
- **Смешение языков.** «Salar, Tashkent Region» латиницей посреди русского текста. Plus code «98MQ+JC» стоит без пояснения, что это такое и как им пользоваться.
- **Цифры-маркетинг.** «100% домашних рецептов» и «500+ счастливых семей» гость никак не может проверить. Такой блок цифр — тоже шаблонный приём.
- **Полные имена авторов отзывов.** Это частные лица, а сайт неофициальный. Хватит имени и инициала.
- **Нигде не сказано, что это концепт.** Посетитель может принять сайт за официальный.

## UX

- **Нет главного для ресторана: открыто ли сейчас.** Часы работы есть только в самом низу.
- **Кнопка «Забронировать стол» ничего не бронирует,** а просто прокручивает страницу вниз. Честнее сразу позвонить: бронь всё равно по телефону.
- **Нет меню и цен.** Это нормально для концепта, но об этом стоит прямо сказать и дать понятное действие («цены — по телефону»).
- **Тяжёлая карта Google.** iframe тянет около мегабайта сторонних скриптов и ставит cookies ещё до того, как человек решил, что ему нужна карта.
- **Маршрут только через Google Maps.** В Узбекистане многие пользуются Яндекс Картами, да и в такси адрес удобнее скопировать.

## Доступность (a11y)

- Нет ссылки «Перейти к содержанию» и видимых стилей `:focus-visible`.
- Ссылки в тексте отличаются от обычного текста только цветом (`a { text-decoration: none }`).
- Контраст: золотые надзаголовки на светлом фоне — 2,37:1, кнопка B1 — около 1,3:1. Норма WCAG AA — 4,5:1.
- `scroll-behavior: smooth` и бесконечная анимация работают даже у тех, кто отключил анимации в системе.
- Эмодзи-иконки не скрыты от скринридеров (`aria-hidden`).

## Производительность

- Шрифты грузятся с двух сторонних доменов, CSS блокирует отрисовку. Для `fonts.gstatic.com` нет `preconnect` с `crossorigin`.
- iframe Google Maps — основной вес страницы.
- Обработчик `scroll` (`script.js:5`) срабатывает на каждый кадр прокрутки, хотя достаточно `IntersectionObserver`.
- `transition: all` (`style.css:65`) анимирует лишние свойства.

## SEO и превью в соцсетях

- Нет Open Graph и Twitter-тегов: ссылка в Telegram придёт без картинки и описания.
- Нет `canonical`, `favicon`, `theme-color`, `robots.txt`, `sitemap.xml`.
- Нет структурированных данных (schema.org `Restaurant`), по которым поисковик понимает адрес, телефон и часы.
- Нет страницы 404.

## Код и структура

- **Нет единого источника данных.** Телефон повторяется в коде 4 раза, адрес дважды. Изменишь в одном месте, забудешь в другом.
- Инлайн-стили в HTML (`index.html:106`, `148`, `173`).
- Мёртвый код: `background-size: cover` у градиентов, правило для `img` (картинок нет), `.section h2.center, p.center`.
- `overflow-x: hidden` на `body` маскирует ошибки вёрстки, а не исправляет их.
- В корне лежит рабочий файл с промптом `## Дизайн убрать «ИИ-стиль».txt`: пробелы и спецсимволы в имени, к продукту он не относится.

## Безопасность

- Секретов нет, и это хорошо.
- Нет Content Security Policy. На GitHub Pages заголовки не настроить, но можно задать CSP через `<meta>`.
- Сторонние запросы (Google Fonts, Google Maps) уходят без ведома пользователя. Это вопрос приватности.
- `referrerpolicy="no-referrer-when-downgrade"` у карты передаёт Google полный адрес страницы. Безопаснее значение по умолчанию.

## Инфраструктура проекта

Нет README, LICENSE, CHANGELOG, `.gitignore`, `.editorconfig`, линтеров, форматтера, тестов, CI и деплоя. Проверить, что сайт работает, может только человек глазами.

## План

1. Перенести сайт на Eleventy. Все данные о ресторане — в `src/_data/restaurant.json`, из него собираются HTML, JSON-LD и данные для скриптов.
2. Дизайн-система в CSS-токенах. Новая вёрстка главной и 404, без фальшивых фото и эмодзи.
3. Новые тексты.
4. Клиентские модули: меню, статус «открыто сейчас», карта по клику, копирование адреса. Всё работает и без JS, скрипты только улучшают.
5. Тесты: юнит-тесты логики на `node:test`, e2e и axe на Playwright.
6. Линтеры (ESLint, Stylelint, Prettier, html-validate), проверка типов JSDoc через TypeScript.
7. CI в GitHub Actions: lint → test → build → e2e → Lighthouse. Деплой на GitHub Pages.
8. SEO: OG-картинка, favicon, sitemap, robots.
9. README со скриншотами и схемой, LICENSE, CHANGELOG, REPORT.md.
